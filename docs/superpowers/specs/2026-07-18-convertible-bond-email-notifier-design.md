# 可转债申购邮件提醒程序设计

日期：2026-07-18  
状态：已完成口头设计确认，待用户审阅书面规格

## 1. 目标

构建一个无需自有服务器的 Python 程序。程序每天北京时间 09:30 在
GitHub Actions 中运行，查询 A 股市场当天可申购的可转换公司债券：

- 当天有一只或多只可申购转债时，合并为一封邮件，通过 QQ 邮箱发送。
- 当天没有可申购转债时，正常结束，不发送邮件。
- 数据获取、结构校验或配置发生异常时，尽可能发送异常提醒，并让
  GitHub Actions 任务以失败状态结束。

本程序只提供信息提醒，不构成投资建议。用户申购前仍应以交易所公告和
证券账户展示的信息为准。

## 2. 范围

### 2.1 包含

- 沪深 A 股市场向公众发行、申购日期为执行当天的可转换公司债券。
- 东方财富可转债数据接口的读取、校验和字段映射。
- QQ 邮箱 SMTP SSL 发信。
- GitHub Actions 定时执行和手动执行。
- HTML 与纯文本两种邮件正文。
- 自动化测试、中文部署文档和故障排查说明。

### 2.2 不包含

- 可交换债、普通公司债、新股申购和港美股债券。
- 自动申购、券商账户登录或任何交易操作。
- 网页界面、移动应用、数据库或历史提醒查询。
- 估值、收益预测、申购建议或投资评级。
- 跨多数据源自动比对。数据源改版时通过异常提醒暴露问题，再人工更新适配器。

## 3. 总体架构

系统由五个边界清晰的部分组成：

1. **调度器**：GitHub Actions 每个自然日按 `Asia/Shanghai` 时区在
   09:30 触发，也允许手动触发。
2. **数据客户端**：使用 HTTPS 请求东方财富数据中心
   `RPT_BOND_CB_LIST` 报表。
3. **解析与筛选器**：校验响应结构，将原始字段转换为内部转债对象，并按
   北京时间当天日期严格筛选。
4. **邮件渲染器**：将零只、一只或多只转债转换为纯文本和 HTML 内容。
5. **邮件发送器**：通过 `smtp.qq.com:465` 的 SMTP SSL 连接发送邮件。

各部分通过普通 Python 数据对象和显式函数接口连接，网络访问与业务逻辑分离，
从而允许测试使用固定样例而不访问真实接口或真实邮箱。

## 4. 调度与执行

GitHub Actions 工作流包含以下触发方式：

- `schedule`：每天北京时间 09:30 执行。
- `workflow_dispatch`：允许用户从 Actions 页面手动执行。
- `push` / `pull_request`：只运行测试，不发送真实邮件。

定时工作流使用标准 Ubuntu runner 和 Python 3.12。单次任务依次执行：

1. 检出代码。
2. 安装锁定范围内的 Python 依赖。
3. 运行自动化测试。
4. 从 GitHub Secrets 注入邮件配置。
5. 启动一次提醒检查。

GitHub 的计划任务可能因平台负载而延迟，因此 09:30 是目标触发时间，不承诺
秒级准时。工作流存在于默认分支，并使用 `Asia/Shanghai` 时区，避免手工换算
UTC 和夏令时问题。

## 5. 数据获取与模型

### 5.1 请求策略

数据客户端直接访问东方财富数据中心的可转债列表接口，请求参数至少包括：

- `reportName=RPT_BOND_CB_LIST`
- `columns=ALL`
- `sortColumns=PUBLIC_START_DATE`
- `sortTypes=-1`
- `source=WEB`
- `client=WEB`

客户端设置 5 秒连接超时和 15 秒读取超时。对于连接中断、超时、HTTP 429 和
HTTP 5xx，最多进行 3 次请求尝试，并采用短暂递增退避。其他 HTTP 4xx、
非 JSON 响应和结构错误立即失败。

程序获取按申购日期倒序排列的最新数据页。由于该报表包含历史转债，完整响应
不应为空；空报表、`result` 缺失或 `data` 不是列表均视为数据源异常，而不是
“今天没有新债”。

### 5.2 内部转债对象

解析器将原始记录映射为以下字段：

- 债券名称
- 债券代码
- 申购代码
- 申购日期
- 正股名称
- 正股代码
- 发行价格
- 申购上限
- 债券评级

债券名称、债券代码和申购日期是关键字段。当天候选记录缺少任何关键字段、
日期无法解析，或字段类型明显异常时，整个检查失败并进入异常提醒流程，避免
把接口改版误报为“无新债”。其余展示字段若数据源未提供，则在邮件中显示
“—”，同时保留债券的有效提醒。

程序以 `zoneinfo.ZoneInfo("Asia/Shanghai")` 得到业务日期，仅比较日期部分，
不依赖 GitHub runner 的本地时区。

## 6. 邮件通知

### 6.1 GitHub Secrets

部署时需要配置：

- `SMTP_USERNAME`：完整 QQ 邮箱地址。
- `SMTP_AUTH_CODE`：QQ 邮箱生成的 SMTP 授权码，不是 QQ 登录密码。
- `MAIL_TO`：一个或多个收件地址；多个地址使用英文逗号分隔。

代码中固定使用 `smtp.qq.com`、端口 `465` 和 SSL。Secrets 不写入仓库、
测试样例、错误邮件或任务日志。日志中的邮箱地址只在必要时显示，授权码绝不
回显。

### 6.2 申购提醒

邮件主题格式：

`[新债申购提醒] YYYY-MM-DD 共 N 只可转债`

同一天的全部转债合并为一封邮件。HTML 版本使用简单表格展示第 5.2 节字段，
纯文本版本逐只列出同样的信息。正文结尾注明数据来源、查询时间和风险提示。

### 6.3 无申购

数据响应通过校验但筛选结果为空时：

- 输出一条不含敏感信息的正常日志。
- 不连接 SMTP。
- 进程以退出码 0 结束。

### 6.4 异常提醒

数据请求、解析、日期筛选或配置校验异常时，程序生成：

`[新债提醒任务异常] YYYY-MM-DD`

正文包含失败阶段、简洁错误类型、北京时间和 GitHub Actions 运行链接；不包含
授权码、完整响应正文或其他敏感信息。

如果数据流程失败但 SMTP 可用，发送异常邮件后仍以非零退出码结束。如果 SMTP
本身失败或邮件配置缺失，程序记录经过脱敏的错误并以非零退出码结束；此时无法
通过同一失效邮箱发送异常通知，用户可依赖 GitHub Actions 的失败状态和 GitHub
自身的工作流失败通知。

## 7. 配置校验与安全

程序启动时检查三个 Secrets 是否存在、收件地址列表是否非空，以及发件地址
格式是否基本有效。配置值只从环境变量读取。

项目使用最小 GitHub Actions 权限 `contents: read`，不授予写仓库、发 Issue
或访问其他服务的权限。不记录完整接口响应，防止日志膨胀；错误诊断只记录响应
状态、结构缺失位置和追踪信息。

建议使用私有 GitHub 仓库，并在 GitHub 账单预算中启用“达到额度后停止使用”，
避免意外产生超额费用。该每日轻量任务的预计用量远低于 GitHub Free 当前每月
2,000 分钟的 Actions 额度。

## 8. 代码组织

计划采用以下职责划分：

- `src/new_bond_notifier/models.py`：内部转债对象和配置对象。
- `src/new_bond_notifier/eastmoney.py`：HTTP 请求、重试和原始字段适配。
- `src/new_bond_notifier/service.py`：日期筛选和单次任务编排。
- `src/new_bond_notifier/emailer.py`：邮件渲染与 SMTP 发送。
- `src/new_bond_notifier/cli.py`：环境变量读取、日志和退出码。
- `tests/`：单元测试、固定响应样例和模拟集成测试。
- `.github/workflows/new-bond-notifier.yml`：定时与手动提醒工作流。
- `.github/workflows/tests.yml`：代码更新时的测试工作流。
- `README.md`：中文部署、测试和故障排查说明。

## 9. 测试策略

自动化测试不访问真实东方财富接口，也不发送真实邮件。测试覆盖：

- 北京时区下日期边界和严格日期匹配。
- 正常响应且当天无申购。
- 当天一只申购和同日多只申购。
- 可选展示字段缺失时使用“—”。
- 关键字段缺失、日期非法、响应为空和接口结构变化时失败。
- 临时网络错误重试，永久错误不进行无意义重试。
- HTML 和纯文本正文包含全部转债且正确转义特殊字符。
- SMTP 调用使用 SSL、正确发件人和全部收件人。
- Secrets 缺失、授权失败和 SMTP 连接失败时返回非零退出码。
- 异常邮件失败时仍保留原始数据错误作为主错误。

测试完成后还需进行一次受控部署验证：

1. 在私有仓库配置 Secrets。
2. 手动触发工作流。
3. 在没有当日新债时确认任务成功且不发申购邮件。
4. 使用测试夹具运行邮件渲染/发送入口，确认 QQ 邮箱实际可收信。
5. 确认 Actions 日志未出现授权码或完整敏感配置。

## 10. 验收标准

满足以下条件即认为首版完成：

- 每天北京时间 09:30 的 GitHub Actions 定时配置有效。
- 手动运行入口有效。
- 当天有可申购 A 股可转债时，一封邮件列出全部匹配转债。
- 当天无可申购转债时不发送邮件且任务成功。
- 数据源或数据结构异常时发送异常邮件并将任务标记为失败。
- SMTP 无法使用时任务失败且日志不泄露授权码。
- 自动化测试全部通过。
- README 能让用户独立完成 QQ SMTP 授权码和 GitHub Secrets 配置。

## 11. 已知限制

- 东方财富网页数据接口免费且无需 API Key，但不是带服务等级承诺的正式付费
  API；接口或字段变化时需要更新适配器。
- GitHub Actions 的计划任务可能延迟，极端情况下可能被平台丢弃。用户可通过
  Actions 历史和 GitHub 自身的失败通知进行检查。
- 本设计不建立第二数据源，因此不能自动发现“接口返回了格式正确但业务数据
  本身错误”的情况。
- 手动重复执行会重复发送申购提醒；首版不引入数据库或跨运行状态来去重。
